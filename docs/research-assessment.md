# 가전제품 낙하 AI의 적용 범위와 실험 판단

기준일은 2026년 10월 15일이다. 공개 코드 조사와 실제 실행을 함께 사용한다. 수치 실험의 세부 설정과 결과는 `outputs/`의 실행별 기록을 우선한다.

## 현재 기술 판단

PhysicsNeMo는 공개 FEM 데이터를 이용한 충돌·낙하 대리모델을 구축할 수 있는 후보 프레임워크다. 공식 저장소에는 범퍼와 차체 충돌, 휴대폰 낙하, OpenRadioss 데이터 생성 경로가 있다. 따라서 선형 탄성 PINN이나 준정적 판 예제만으로 가능성을 판단할 필요는 없다. [공식 구조역학 예제](https://github.com/NVIDIA/physicsnemo/tree/main/examples/structural_mechanics)

전체 조립체도 연구 대상이 될 수 있다. NVIDIA와 GM 등의 차체 연구는 많은 부품을 포함한 FEM 궤적의 대리모델을 다룬다. 그러나 특정 설계·접촉·충돌 조건의 결과를 학습한 모델이라는 범위를 유지해야 한다. 이 근거가 임의의 TV·세탁기 조립체, 새로운 접촉 topology, 유리 파손이나 체결부 파괴까지 일반화하는 solver를 입증하지는 않는다. [차체 충돌 연구](https://arxiv.org/abs/2510.15201), [FLARE 충돌 연구](https://arxiv.org/abs/2605.27758)

첫 실용 목표는 검증된 조건 범위 안에서 설계안의 순위를 정하고, 위험한 조건을 골라 고정밀 FEM으로 재검토하는 것이다. AI 단독으로 합격 판정을 내리려면 예측 오차뿐 아니라 위험 누락률과 조건 이탈 검증이 추가로 필요하다.

## 전체 제품과 부품의 선택 기준

전체 제품 접근은 같은 제품군에서 부품 연결과 접촉 정의가 유지되고, 변경 파라미터가 제한되며, 검증된 원 FEM을 반복 생성할 수 있을 때 유망하다. 부품별 오차와 에너지·접촉 응답을 추적하고, 새로운 설계에서도 메시와 출력의 대응을 확보해야 한다.

부품 또는 서브어셈블리를 먼저 다루는 편이 유리한 경우는 파손이 특정 브래킷·캐비닛·패널·체결부에 집중되거나, 조립체 데이터 생성 비용이 크거나, 설계 변경으로 접촉·메시 연결이 자주 바뀌는 경우다. 이때도 전체 제품과의 경계조건 전달을 검증해야 한다. 단순 고정단 조건에서 잘 맞는 부품 모델이 실제 조립체 충격을 잘 맞춘다는 보장은 없다.

세탁기는 캐비닛·프레임·질량체·서스펜션·발·체결부의 상호작용을, TV는 프레임·패널·스탠드·체결부 및 포장재를 고려할 수 있다. 이는 제품별 세부 모델이 없는 현재 단계의 후보 분해이며 확정된 연구 범위는 아니다.

## 예측할 출력과 검증 방법

| 출력 후보 | 실용적인 판단 | 필요한 검증 |
|---|---|---|
| 잔류 변형과 주요 간극 | 조립성·외관·간섭 | 부품별 변위, 잔류값, 최대값과 발생 위치 |
| 응력·소성변형률 | 국부 위험 순위 | 단위·적분점/절점 평균화 정합, hotspot·상위 분위수 |
| 가속도 | 전자부품·내부 질량체 충격 | 센서 위치, 필터, peak·peak 시간·주파수 응답 |
| 접촉력 | 하중 경로와 충격 pulse | 접촉 정의, peak·impulse·접촉 시작/종료 시간 |
| 운동·내부·접촉·hourglass 에너지 | 해석 품질과 흡수 거동 | 물리 에너지 수지와 수치 에너지 구분 |
| 파손 위험 | 위험 케이스 선별 | 손상 법칙·파손 라벨, false negative, 불확실성 |

변위의 공간 평균 오차가 작아도 국부 응력과 가속도가 정확하다는 뜻은 아니다. 가속도는 변위의 시간 미분에 민감하므로 충분한 시점과 동일한 필터 기준이 필요하다. 응력·접촉력·파손 라벨이 없는 데이터셋에서는 해당 정확도를 평가하지 않는다.

학습과 검증은 독립 해석 케이스 단위로 나눈다. 동일 FEM 궤적의 이웃 시점을 양쪽으로 나누면 조건 일반화 성능을 과대평가할 수 있다. 정규화는 학습 세트에서만 계산하고, 모델 선택은 내부 검증 세트로 하며, 최종 테스트는 마지막 평가에 사용한다. 후속 실험은 낙하 높이·방향·접촉 상태·설계 범위 밖 조건을 따로 남겨 외삽을 확인해야 한다.

## 비교할 알고리즘

| 방법 | 유망한 조건 | 주요 한계와 비교 목적 |
|---|---|---|
| 평균·선형/커널 회귀·POD ROM | 고정 메시, 적은 설계 변수 | 저비용 기준선. 새로운 topology·불연속 접촉·분기 좌굴에 약할 수 있음 |
| MLP·tree 기반 지표 모델 | 최대값·에너지·파손 지표 등 적은 출력 | 전체 장을 재구성하지 않지만 DOE 탐색에 유용 |
| MeshGraphNet | 메시 연결과 국부 상호작용 활용 | 간선·상태·접촉 graph 구성, 긴 rollout 오차 축적 |
| Transolver·GeoTransolver·GeoFLARE | 장거리 결합과 형상/조건을 포함한 field surrogate | 데이터 범위·메시 규모·조건화 방식에 따라 검증 필요 |
| PINN·에너지 기반 학습 | 단순 PDE·경계조건, 물리 제약 보강 | 마찰·소성 history·불연속 접촉·파손을 포함한 대형 explicit 문제의 첫 대체법으로 단정하기 어려움 |
| FEM과 AI/ROM 결합 | 일부 부품 또는 계산 단계만 가속 | 경계조건·접촉·에너지 전달 오차를 함께 검증해야 함 |

One-shot은 전체 시간 궤적을 한 번에 예측하고, time-conditional 모델은 시간을 조건으로 장을 예측한다. Autoregressive 모델은 상태를 순차 갱신한다. 계산 비용과 장기 오차의 양상이 다르므로 사용자 문제에서 순위를 비교해야 한다. 기존 논문의 우승 모델을 미리 확정하지 않는다.

## 공개 범퍼 데이터 실험의 의미

공개 `AIRBORNEPANDA/BumperBeamCrashExample`을 실제 내려받아 사용한다. 원 데이터 설명은 OpenRadioss 범퍼와 강체 pole 충돌이다. PhysicsNeMo의 범용 crash README가 LS-DYNA를 설명하는 것과 구분한다. 이 데이터에는 해석 조건별 VTP와 global feature가 있다. [공개 데이터](https://huggingface.co/datasets/AIRBORNEPANDA/BumperBeamCrashExample)

실파일은 기본적으로 11시점의 displacement와 thickness를 담고 있으며, 두 케이스에는 추가 시점이 있다. 공통 시간 구간을 정렬한 실험과, 공식 기본 51시점·응력·소성변형률 구성을 그대로 재현하는 실험은 다르다. 속도 값이 일정한 이 데이터로 새로운 속도에 대한 일반화 성능을 검증할 수 없다.

작은 학습 모델이 평균·커널 회귀보다 좋아지는지 확인한 뒤, 절점 수·모델 크기·시간 전략을 늘린다. 설치와 한 step의 학습 성공은 수렴이나 설계에 쓸 정확도와 구분한다. 현 데이터의 정확도는 세탁기·TV 정확도로 환산하지 않는다.

## FEM 데이터 생성과 회사 환경 확장

개인 환경은 OpenCourant/OpenRadioss 입력 → starter/engine → animation 및 time history → VTK 또는 d3plot → VTP/VTU/Zarr → 학습·추론·FEM 비교 경로를 구성할 수 있다. 실제 작은 OpenCourant 회귀 모델 실행과 결과 변환은 별도 실행 기록에 남겼다. 회귀 기준값 일치와 제품 재료·단위·물리 실험 검증은 서로 다르다.

상용 Radioss·HyperMesh 연계에서는 회사에서 검증한 원 모델과 승인된 해석 조건으로 데이터 생성 자동화를 만든다. 부품·절점·요소 ID, 재료·두께·접촉 정의, 단위, 초기 속도·방향, 시간 간격 및 failure 상태를 메타데이터에 보존한다. 응력의 적분점 값과 절점 평균 값도 구분해야 한다. 회사 모델을 개인 공개 저장소나 외부 Cloud에 넣는 것은 이번 작업에 포함되지 않는다.

현재 NVIDIA Curator의 예제 경로와 오래된 PhysicsNeMo README 사이에는 이동·명령 차이가 있다. 데이터 생성·변환·학습 소스의 버전을 함께 고정해야 한다. 공개 deck의 비상업 조건이나 데이터셋의 라이선스 미표시는 회사 상업 연구 데이터의 사용 권한을 대신하지 않는다. [Curator 현재 예제](https://github.com/NVIDIA/physicsnemo-curator/tree/main/examples/cae)

## 후속 실험의 판단 기준

현 단계에서 적정 DOE 수·GPU 대수·수렴 epoch를 확정하지 않는다. 다음 비교는 학습곡선, 독립 케이스 오차, baseline 대비 향상, GPU 메모리와 처리량을 근거로 정한다. 입력 조건의 수와 범위는 실제 재료·낙하 방향·접촉 변화의 복잡성에 따라 달라진다.

유료 GPU가 필요한 경우에는 먼저 측정한 메모리·처리량에 맞는 카드와 총 점유 시간 예산을 제시한다. 공개 시간당 단가는 `resource-options.md`에 있으며 최종 재고·저장·전송·세금은 별도로 확인한다. 추가 과금은 승인 전 실행하지 않는다.
