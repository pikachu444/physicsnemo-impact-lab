# 공개 FEM 데이터로 실행한 PhysicsNeMo 학습과 검증

2026년 10월 15일, 공개 범퍼 충돌 FEM 데이터로 실제 설치·학습·추론·수치 비교를 수행했다. **로컬 RTX 3060 Laptop GPU에서 전체 변형체 메시 학습까지 성공했다.** 이 범퍼의 제한된 조건에서 변위 예측이 가능함을 확인한 결과이며, 가전제품 조립체의 낙하·응력·파손 정확도를 검증한 결과는 아니다.

## 실행 위치와 환경

| 위치 | 실제 확인한 내용 |
|---|---|
| Codex Cloud 환경 설정 인스턴스 | Python 3.12.14, cgroup CPU 4코어 상당·RAM 32 GiB, 첫 디스크 여유 29.83 GiB. NVIDIA 장치 노출 없음. GitHub·PyPI 접근 및 승인 후 Hugging Face API/조건 JSON 접근 성공 |

현재 대화의 주 실행 위치는 로컬이다. Cloud 환경은 별도로 생성해 검사·게시했다. 실행 장소는 승인을 묻는 방식과 별개이며, Cloud 작업은 게시된 환경을 선택해 시작한다. [공식 Cloud 환경 문서](https://learn.chatgpt.com/docs/environments/cloud-environments)

전용 GPU 환경의 다운로드는 약2.77 GB, 보존 중인 휠을 포함한 작업 디스크는 약7.29 GB였다. 데이터/출력/다른 실험은 이 수치에 별도다. 추가 유료 자원·결제는 없었다. 선택한 Transolver 경로는 동작했으나 Warp1.18의 CUDA13 드라이버 요구 경고가 있어 Warp GPU 커널까지 작동한다고 주장하지 않는다. [설치와 기능 검증](../outputs/gpu-experiment/README.md), [Cloud 원본 검사](../results/cloud/README.md)

## 원본과 데이터 범위

PhysicsNeMo 예제 소스는 commit `11685edb3ec1fb6f25665e96cf7a8c4d11a23f16`, 실행 라이브러리는 배포 패키지2.2.2로 고정했다. 소스의 최신 예제와 배포 API 사이의 차이는 아래 호환 기록으로 남겼다.

공개 데이터는 [AIRBORNEPANDA/BumperBeamCrashExample](https://huggingface.co/datasets/AIRBORNEPANDA/BumperBeamCrashExample)의 revision `78f1302fba4d75926c6fdd22d01d5133efc14742`다. Curated VTP132파일(해석131개와 조건 JSON) 약540.26 MB를 확보하고 파일별 SHA256을 기록했다. 전체 RAW_DATA15GB를 모두 내려받지는 않았다.

원본 설명과 `.rad`는 OpenRadioss의 범퍼·강체 pole 충돌이다. 고정된 메시에서 shell 두께와 pole 위치가 바뀌며, 속도는 전 케이스 `-5 mm/ms`로 일정하다. 새로운 속도·낙하 자세·형상·연결 topology의 일반화 시험이 아니다. 원본 `/BEGIN`의 kg/mm/ms 단위를 확인했고 변위는 mm, 시간은 ms로 해석했다.

VTP에는 thickness와 displacement가 있으며 응력·소성변형률·파손 목표는 없다. 전체 VTP점13,676개 중 thickness>0인13,675개를 이 실험의 변형체 절점 집합으로 정의했다. 초기 좌표 정렬을 검사했다. 기본11시점은0,10,…100ms다. Run194/203만110ms가 추가되어 모든 실험은 공통0…100ms를 사용했다.

원본 deck은 Altair의 CC BY-NC4.0 고지를 포함한다. 이 연구의 코드·그림·모델은 공개 데이터에 기반한 개인 비상업 시연으로 출처를 유지한다. 회사용 학습에는 자체 또는 사용 허가를 받은 FEM 데이터를 준비해야 한다. [원본 모델과 공개 구현](https://github.com/HoussemMouradi/OpenRadioss2PhysicsNeMo)

## 설치와 공식 예제 경로에서 해결한 문제

처음부터 학습이 성공한 것으로 기록하지 않았다. 다음 실패와 수정 후 실제 실행을 확인했다.

- 빠진 패키지를 전용 환경에 설치했다. 상속한 전역 패키지의 무관한 충돌3개는 `pip-check.log`에 보존했다. 모든 PhysicsNeMo 기능을 포함한 완전히 독립된 환경 검증은 아니다.
- Windows 기본 인코딩에서 PyTorch compile 보조 소스를 읽는 오류는 UTF-8 실행 설정으로 해결했다.
- main 예제의 `global_dim` 등과 배포된 Transolver API 차이는 별도 실험 YAML로 처리했다.
- 원본 VTP reader는 `displacement_t0.xxx`를 우선 선택해 실제0·10·20…100ms 데이터 중 첫 시점만 읽었다. 원본을 보존하고 시간 이름 정규식 한 줄만 넓힌 호환 reader를 만들었다. 같은 Run100에서 시점1개→11개를 읽는 assert를 확인했다.

그 뒤 **원본 `train.py` + 추가 YAML + 호환 reader**로 CPU에서 Run100/101 학습·Run224 검증, 전체13,676점·2epoch를 실행해 종료코드0과 체크포인트 저장을 확인했다. 이는 공식 실행 경로의 짧은 파이프라인 검증이며 아래 GPU 정확도 실험과 다르다. 별도의 CPU1024점 실험은5epoch 후 GPU 준비에 자원을 우선 쓰도록 중단했으며 완료한 학습으로 계산하지 않았다.

## GPU 학습과 데이터 분할

실제 PhysicsNeMo `Transolver`를 호출하는 작은 실행 드라이버를 작성했다. 원본 공식 crash benchmark의 전체 재현이라고 표현하지 않는다. 모델은2층·폭48·head4·slice8·41,286parameter, Adam과 cosine learning rate, batch1이다. 60epoch는 초기 비교의 계산 예산이며 수렴 보장이 아니다.

공식 TRAINING_DATA124개를 seed20261015로 학습112개·내부 검증12개로 분리했다. 공식 VALIDATION_DATA7개(Run224…230)는 이 GPU 모델의 학습·체크포인트/커널 선택에서 제외한 평가 세트로 썼다. 평균·표준편차는 학습 데이터에서만 계산했다. 체크포인트와 RBF hyperparameter는 내부 검증12개에서 선택했다.

공개 평가 자료이고 Run224는 별도의 CPU 기능 검사에서도 사용됐으므로 완전한 blind test라고 부르지 않는다. 입력 범위 안의 보간 시험이며, 다른 seed·독립 신규 FEM·미관측 형상에 대한 확증 실험은 후속 과제다.

## 같은1024절점에서 비교한 결과

7평가 케이스×1,024점×10개 예측 시점의 결과다. Relative L2는 **변위**의 오차 norm/기준 변위 norm이며 원 좌표를 분모로 쓰지 않았다. 성분 RMSE는 xyz 성분까지 평균한 값이다.

모든 절점에 같은 가중치를 썼다. 체적·질량 가중 오차나 보존법칙 검증이 아니며, 원 좌표를 포함한 position-relative L2를 보고하는 공식 crash 예제·논문의 수치와 직접 비교할 수 없다.

| 방법 | 변위 상대 L2 | 변위 성분 RMSE |
|---|---:|---:|
| 변위0 기준선 | 100% | 84.20 mm |
| 학습 세트의 절점별 평균장 | 20.59% | 17.34 mm |
| 작은 PhysicsNeMo Transolver | 6.38% | 5.37 mm |
| 용량을 늘린 Transolver,4층·폭96 | 5.48% | 4.61 mm |
| RBF kernel field regression | 3.14% | 2.65 mm |

RBF는 global 조건을 정렬된 고정 메시의 출력장에 매핑한다. 12개 gamma/alpha 조합을 내부 검증으로 선택했다. 이번 작은 Transolver보다 정확했지만 새로운 형상·메시의 일반화 능력을 비교한 결과는 아니다. 모델 용량과 학습 설정에 대한 보편적인 우열도 이 한 실험으로 정하지 않는다.

Transolver의 절점·시점별 벡터 오차 P95는18.11mm, 최대46.04mm였다. RBF는 P95=10.97mm, 최대36.45mm였다. 변위 norm 제곱의 약78.23%는 평균 병진 성분이었다. 따라서 상대 L2 하나만으로 국부 찌그러짐·간극·응력 정확도를 판단하면 안 된다.

### 모델 용량에 대한 추가 실험

같은1,024절점·분할·seed·60epoch 예산에서4층·폭96·slice16·head4,293,582parameter로 용량을 늘렸다. 실제 step 메모리와 처리량을 측정한 뒤 실행한 탐색적 비교이며 평가 정답으로 설정을 선택하지 않았다. 학습291.08초, warmed forward9.70ms/해석, Torch 최대 할당65,503,232byte, 표본 최대 RSS1,471,422,464byte였다.

변위 L2=5.4767%와 성분 RMSE=4.6116mm로 평균 오차는 줄었다. 다만 내부 검증 최저점이 마지막60epoch이므로 수렴을 입증하지 않았다. 벡터 오차 P95는14.57mm로 개선됐지만 최대값은112.92mm(Run227,90ms,원 VTP point index10171)로 작은 모델보다 악화됐다. 평균 병진 제거 진단 L2도10.75%로 작은 모델10.06%보다 높았다. **평균 L2 개선을 국부 정확도의 전반적 개선으로 해석하면 안 된다.** 독립 검산에서 같은 절점·시간·기준 FEM 값과 분할을 확인했다. 이 계산 예산 안에서는 RBF 기준선이 가장 낮은 평균 오차를 보였으며, 다른 학습 예산·형상·접촉 조건의 순위는 검증하지 않았다.

## 전체13,675절점으로 학습한 결과

같은 분할·seed·모델·60epoch 예산을 유지하고 학습 절점 수를 전체 집합으로 늘렸다. 메모리·step 시간의 선행 실측에 따른 scale 실험이며 평가 점수로 hyperparameter를 조정하지 않았다. 큰 kernel 회귀 배열은 만들지 않아 RBF 전체 메시 학습 결과는 이 표에 없다.

| 항목 | 실제 측정 |
|---|---:|
| GPU 학습 | 260.53 s,60epoch |
| 내부 검증에서 선택한 epoch | 27 |
| 평가 변위 상대 L2 | 6.1203% |
| 평가 변위 성분 RMSE | 5.1607 mm |
| 평균장 기준선 상대 L2 | 20.5503% |
| 전체 평가 벡터 오차 P95 / 최대 | 17.5929 / 46.8028 mm |
| warmed forward 평균 | 11.79 ms/케이스 |
| PyTorch 최대 할당 GPU 메모리 | 383,345,152 B |
| 표본 관측 최대 process RSS | 1,836,900,352 B |

Forward 시간은 데이터 읽기·전처리·출력 저장을 제외하고 GPU 동기화를 적용한 값이다. GPU 메모리는 Torch allocator 수치로 CUDA context·다른 GPU 프로세스·전체 장치 VRAM과 다르다. RSS는 표본 최대라 진짜 peak의 하한이다. 시스템 여유 RAM은 약0.4…0.8GB까지 적었지만 이 설정의 실제 학습은 완료됐다. 학습 시간에는 내부 검증과 체크포인트 저장이 포함된다.

전체 메시 결과를 기존1,024점에 한정해 다시 계산하면 Transolver6.1616%, 기존 RBF3.1441%였다. 비교 절점의 기준값은 같았다. 이 작은 모델에서는 절점 수 확대만으로 kernel 기준선을 넘지 못했다.

## 저장된 모델 재사용과 독립 검산

저장 체크포인트를 새 모델에 다시 읽어 기존 Run224 예측과 최대 차이0.0mm를 확인했다. 재사용 입력은 선택 절점·초기 좌표 대응을 검사하고, 다른 메시 순서를 조용히 같은 모델에 넣지 않도록 mesh contract를 사용한다.

독립 검토자가 로컬 prediction/기준 NPZ에서 L2·성분 RMSE·벡터 P95/최댓값을 다시 계산했다. GPU1024와 전체 메시 결과 모두 저장 JSON과 수치 정밀도 범위에서 일치했다. 분할 교집합0, 정규화·모델 선택 범위, seed·실행 소스 해시·학습 이력을 확인했다. [독립 검토 기록](experiment-review.md)

그림의 초기 좌표 위 색상장과 `reference+displacement`의 실제 변형 형상을 구분한다. 실제 변형 비교는 배율1배·XY투영이며, FEM/Transolver/RBF에 공통 색 범위를 썼다. 단일 케이스의 예쁜 그림을 전체 평가 수치 대신 사용하지 않는다.

## 같은 범퍼의 원 FEM 재실행

학습 데이터와 별개인 작은 회귀 예제에 더해, 공개 범퍼 **Run224의 원 입력 그대로** OpenCourant 단정밀 solver와2threads로100ms까지 실제 실행했다. Starter4.3997초·Engine742.5954초, 합계746.9951초(약12분27초)이며 종료코드0·정상 종료·100,001cycle을 확인했다. 표본 관측 최대 RSS는 Starter210.1MiB·Engine89.05MiB였다. 처음203초간 실행 후 시간 제한을 늘리려고 중단한 시도는 별도 실패/중단 기록으로 보존하고 완주 시간에 섞지 않았다.

11개 animation과 time history를 VTK/CSV로 변환했다. 원 VTP의 두께>0인13,675점은 초기 좌표와 실제 NODE_ID로 대응시켰다. 시각화용 추가점이나 배열 순서를 그대로 빼지 않았다. 원 VTP 명목100ms에 가장 가까운 새 FEM 저장 시점은 actualTIME=100.001ms로0.001ms 차이가 있으며 시간 보간을 하지 않았다. 이 조건에서 원 공개 데이터와 새 FEM 사이의 최종 변위 성분 RMSE=0.007227mm, 벡터 RMSE=0.012518mm, P95벡터 오차=0.012650mm, 최대=0.113596mm, 변위 상대 L2=0.00886%였다.

양쪽 최종 내부에너지6037J·운동에너지215.2J·보고 에너지 오차−0.4%는 인쇄 정밀도에서 일치했다. 회전 운동에너지와 추가 질량에는 작은 차이가 있었다. 원본과 재실행 모두 초기 penetration 경고가 있으며 수정 없이 기록했다. 이는 원 해석의 수치 재현 확인이며 재료·접촉·충돌 물리를 실험으로 검증한 결과는 아니다. [동일 범퍼 재실행·매핑·로그](../outputs/bumper-fem-rerun/README.md)

FEM 실행 시간과 NN forward 시간은 측정 범위가 다르다. 전처리·데이터 생성·학습·입출력·검증이 포함된 제품 설계 전체의 가속 배수를 이 두 숫자만 나누어 주장하지 않는다.

## 적용 판단

선택한 공개 구조 문제는 보유6GB GPU로 실제 학습·추론·수치 검증까지 가능했다. 이 결과만을 위해 유료GPU가 필수라는 근거는 없다. 후속 대형 형상·시간 해상도·접촉 graph·응력/파손 예제의 자원은 별도로 측정해야 한다.

현재는 제한된 조건의 변위 surrogate와 작은 회귀 기준선을 비교한 단계다. 세탁기·TV로 확장하려면 승인된 제품 FEM, 부품/접촉/재료 메타데이터, 낙하 조건 변화, 충분한 시간 해상도와 독립 검증 기준을 갖춰야 한다. 국부 오차와 위험 누락률이 제품 허용기준을 충족하기 전에는 설계 합격 판정에 사용하지 않는다. [전체 기술 판단과 확장 경로](research-assessment.md)
